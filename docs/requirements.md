## 1. プロダクト概要

**Clipnote**は、HTML・Markdown・プレーンテキスト形式のコンテンツを管理・閲覧するためのツール。Markdownの代替として、より表現力の高いHTML文書を保存・共有すること、および装飾のないメモ書きや会話ログをそのまま残せることを主目的とする。

ユーザー向けには、個別のHTML/Markdown/プレーンテキスト文書を「**クリップ**」と呼称する（DB上のテーブル名・URLパスは引き続き`pages`/`/p/`を使用。詳細は設計書0章）。

### 基本的な利用フロー

1. 管理画面から、またはMCP対応クライアント（Claude等）からHTML・Markdown・プレーンテキストいずれかのコンテンツを登録
2. 公開設定（`private` / `public`）を行う
3. 個別クリップ、または複数クリップをまとめた「コレクション」のURLを公開できる
4. ブラウザから閲覧（本人は管理画面経由、他者は公開URL経由）

### ユーザー獲得（LP）の訴求ポイント

- AIとの会話で生成させたHTML/Markdown、あるいは会話ログやメモ書きをそのまま保存して管理・閲覧できる
- **AI（Claude等）との会話から直接クリップを作成・更新できる（MCP連携、v6で追加）**
- HTML/Markdown/プレーンテキストのコンテンツにユニークな公開URLを発行して共有できる
- 複数のコンテンツをコレクションとしてまとめて管理・公開できる

## 2. ユーザー

| フェーズ | 内容 |
| --- | --- |
| 認証（Web） | better-auth（メール/パスワード方式） |
| 認証（MCP、v6で追加） | APIキー方式。ユーザーが管理画面から発行・失効できる |
| 認証（MCP、v7で追加） | OAuth 2.1方式（Authorization Code + PKCE + 動的クライアント登録）。APIキー方式と併存し、いずれもWebのログインセッションと同じ`users`テーブルを参照する |

- 各ユーザーは自分のクリップ・コレクション・APIキー・OAuth連携のみ管理画面で編集できる
- 公開設定された（`public`の）クリップ・コレクションは、ログインなしで誰でも閲覧できる
- v7で追加したOAuth 2.1は、あくまでMCP（`mcp.clipnote.paritto.dev`）向けの認可サーバーとしてClipnote単体で完結させる。別リポジトリ`paritto-auth`が担うエコシステム全体（Paritto）のSSO統合は引き続き将来検討とし、混同しないこと（16章参照）

## 4. 対応コンテンツ形式

| 形式 | 保存方式 | 表示方式 |
| --- | --- | --- |
| HTML | そのまま保存 | 別ドメインiframeでレンダリング |
| Markdown | そのまま保存（ソース） | 別ドメインiframeでレンダリング（unified/remark/rehypeビューワー経由） |
| **プレーンテキスト（v9で追加）** | **そのまま保存** | **別ドメインiframeでレンダリング（構文はいっさい解釈せず、改行・空白を保持したまま表示）** |

保存されるHTML/Markdownは無害化（サニタイズ）処理を行わない。プレーンテキストは構文を解釈しない形式のため、表示時にHTML特殊文字をエスケープするが、これは危険なコンテンツを除去する無害化とは異なる（元々実行される余地がない）。管理画面経由・MCP経由いずれの登録でも同じ方針とする。

## 5. 機能要件

### 5-1. クリップ管理

- クリップの**新規作成**（管理画面のダイアログ、または**MCP経由の`upload_page`、v6で追加**）
- クリップ本文の**更新（全文差し替え）**（管理画面のダイアログ、または**MCP経由の`update_page`、v6で追加**）
- クリップのメタデータ（タイトル・公開設定・所属コレクション）の**編集**（管理画面のみ）
- クリップの**削除**（管理画面のみ。MCP経由の削除は対象外）
- クリップの**公開設定**（クリップ単位：`private` / `public`）

### 5-2. 新規作成・本文更新の入力方式（管理画面）

- **貼り付け**：管理画面のダイアログ内テキストエリアに全文をペースト
- **ファイルから読み込み**：ファイルを選択またはドラッグ&ドロップすると、サーバーへアップロードせずクライアント側でファイル内容とファイル名を読み取り、本文・タイトルの初期値へ即時反映する

### 5-3. コンテンツバリデーション

- HTML/Markdownとしての厳密な構文検証は行わない（プレーンテキストはそもそも構文を持たないため対象外）。空文字列・不正なUTF-8エンコーディングのみを拒否する
- 本文サイズの上限は**1MB（1,048,576 bytes、UTF-8換算）**とし、クライアント側・サーバー側の両方でチェックする
- **管理画面経由・MCP経由いずれのバリデーションも共通のロジックを使用する（v6で明確化）**

### 5-4. 更新履歴・バージョン管理

- 本文更新のたびに、更新前のバージョンを履歴として保存する
- 直近**10件**のバージョンを保持する
- 過去のバージョンをプレビューし、任意のバージョンへ**復元**できる
- 現在のバージョン・過去のバージョンいずれも、ファイルとしてダウンロードできる。復元は過去のバージョンにのみ提供する
- **MCP経由の`update_page`による更新も、管理画面と同じ`page_versions`退避ロジックを通る（v6で明確化）**

### 5-5. 閲覧

- 公開URL `/p/[uuid]` でコンテンツをレンダリング
- `private`クリップは認証必須（かつ自分のクリップのみ）
- `public`クリップは認証なしで誰でも閲覧可
- 管理画面内でもプレビュー表示

### 5-6. コレクション管理

- 管理画面から作成・編集・削除
- コレクションは「クリップの一覧ページ」として機能する
- コレクションには名前・説明を持つ
- 1クリップが複数コレクションに属せる（多対多）
- コレクションには専用の一覧ページ `/c/[uuid]` が生成される
- コレクション自体も公開設定（`private` / `public`）を持つ
- 公開コレクションに非公開クリップが含まれる場合、そのクリップは一覧表示から除外する
- 所有者本人が認証済みで閲覧する場合は、公開設定を問わず全所属クリップを表示する
- 所属クリップの**並び替え**が可能（デスクトップはドラッグ&ドロップ、モバイルは並び替えモード＋上下移動ボタン）
  - **デスクトップ：ドラッグ中はドロップ予定位置にプレースホルダーを表示。ドロップ確定時に1回のAPIコールで一括送信（v6で明確化）**
  - **モバイル：並び替えモード中の移動はローカル状態のみ反映し、「完了」押下時に1回のAPIコールで一括送信。「完了」を押さずに画面を離れた場合は変更を破棄する（v6で確定）**
- 所属クリップの**追加**は、自分の全クリップから検索・複数選択するダイアログで行う
  - **一覧は更新日時の新しい順、検索はタイトル部分一致、各行に形式バッジを表示する（v6で確定）**
- コレクションから「**外す**」（関連付けの解除のみ、クリップ自体は残る）と、クリップ自体の「**削除**」は明確に別操作として区別する
- **新規作成完了後は詳細画面へ自動遷移し、「クリップを追加」ダイアログを開いた状態にする（v6で確定。作成と追加の往復を削減する導線）**
- **コレクション一覧では、行クリックで詳細画面へ遷移する（クリップ一覧の「クリックでプレビュー」とは非対称。v6で確定）**
- **コレクション詳細画面には、公開URLコピーと「公開ページで見る」リンクを表示する（v6で追加）**

### 5-7. タグ管理

MVP対象外として確定。コレクションのみでの分類とし、フィルタリング・検索が必要になった段階で次フェーズとして追加する。

### 5-8. 管理画面

- **認証**：better-auth（メール/パスワード、サインアップ・ログイン）
- **クリップ一覧**：形式・タイトル・公開設定・所属コレクション・更新日時・公開URLコピー。デスクトップはテーブル形式、モバイルはカード形式に切り替える
- **クリップ詳細**：コンテンツプレビュー、更新履歴の確認・復元、所属コレクションの確認、公開設定の変更
- **新規作成・メタデータ編集・本文更新**：いずれもダイアログで完結
- **コレクション一覧**：コレクション名・説明・公開設定・所属クリップ数。**行クリックで詳細画面へ遷移。オーバーフローメニューは「編集」「削除」のみ。説明未入力は「説明なし」表示（v6で確定）**
- **コレクション詳細**：コレクション情報・公開設定の編集、所属クリップの追加・削除・並び替え、**公開URLコピー・公開ページへのリンク（v6で追加）**
- **APIキー管理（v6で追加）**：`/admin/api-keys`にて、名前を付けてのAPIキー発行（発行直後のみ生キー全文を表示）・一覧（マスク表示、最終利用日時）・失効を管理
- **削除**（クリップ・コレクション・APIキーそれぞれ）

画面設計の詳細は設計書v13 6章・7章・8章を参照。

### 5-9. MCPサーバー（v6で新規追加）

MCP対応クライアント（Claude Desktop、Claude Code等）から、Clipnoteのクリップを直接操作できる機能。`mcp.clipnote.paritto.dev`で稼働。

| ツール | 内容 |
| --- | --- |
| `list_pages` | 自分のクリップ一覧を取得（タイトル検索対応、本文は含まない） |
| `get_page` | 指定uuidのクリップを本文込みで取得 |
| `upload_page` | 新規クリップを作成（content・content_type・title・visibility） |
| `update_page` | 既存クリップの本文を全文差し替え |

- 認証はAPIキー（Bearerトークン）方式、またはOAuth 2.1方式（Authorization Code + PKCE + 動的クライアント登録、v7で追加）のいずれか。前者は8章のAPIキー管理画面で発行したキーを使用し、Claude Desktop・Claude Code等の直接Bearerトークンを設定できるクライアント向け。後者はclaude.aiのカスタムコネクタ等、OAuthの動的クライアント登録が前提のクライアント向けで、既存のWebログインセッションでの認可＋同意画面（`/oauth/consent`）を経て発行する
- OAuthで連携したアプリは、`/admin/api-keys`内の「連携中のアプリ」から確認・失効できる（v7で追加）
- `upload_page`時点でのコレクションへの割当は行わない（管理画面から手動で割り当てる運用）
- クリップの削除、コレクションの作成・編集はMCP経由では対象外（将来検討）

詳細は設計書v13 13章を参照。

---

### 5-10. アカウント管理（v8で新規追加）

better-authのコア機能（追加プラグイン不要）で実現する、ログイン以外のアカウント関連機能。

| 機能 | 内容 |
| --- | --- |
| パスワードリセット | `/forgot-password`でメールアドレスを入力→再設定用リンクをメール送信→`/reset-password`で新パスワードを設定。メールアドレスの登録有無に関わらず同じ成功メッセージを表示し、登録有無の推測（ユーザー列挙）を防ぐ |
| メール確認 | サインアップ時に確認メールを自動送信。**任意**（未確認でもクリップ作成・閲覧等の機能は制限しない）。`/admin`配下に未確認バッジ＋再送信ボタンのバナーを表示 |
| パスワード変更 | ログイン中ユーザーが現在のパスワードを入力した上で変更。変更時は他端末のセッションを無効化する |
| アカウント設定画面 | `/admin/settings`。名前・メールアドレス・メール確認状態を表示し、パスワード変更はダイアログで行う（設計書0章・6章・7章のダイアログ方針に準拠） |

メール送信はCloudflare Email Service（`send_email`バインディング）を使用。送信元ドメイン（`paritto.dev`）のEmail Sending有効化はCloudflareアカウントに対する手動作業として別途実施する。未有効化の間・開発環境では、メールを実送信せずリンクをサーバーログに出力するフォールバックで動作する。

詳細は設計書v13 16章を参照。

## 6. URL設計（概要）

`/p/[uuid]`（個別クリップ）、`/c/[uuid]`（コレクション一覧）、`/admin`配下（管理画面）、`/admin/api-keys`（APIキー管理・連携中のアプリ管理、v6で追加、v7でOAuth連携管理を追加）、`/admin/settings`（アカウント設定、v8で追加）、`/forgot-password`・`/reset-password`（パスワードリセット、v8で追加）、`/oauth/consent`（OAuth同意画面、v7で追加）、`/login`・`/signup`の構成。MCPサーバー側にも`/.well-known/oauth-protected-resource`（v7で追加）がある。詳細は**Clipnote設計書v13 3章**を参照。

## 7. UI／UXデザイン方針（概要）

管理画面（APIキー管理含む）はshadcn/ui + Tailwind CSSでCRUD作業に適した構成とし、LP・公開ページのiframe外枠はブランド訴求を重視したカスタムTailwind実装とする。詳細は**Clipnote設計書v13 2章**を参照。

---

## 8. セキュリティ設計（概要）

コンテンツは別ドメインからiframe配信し、sandbox属性で実行コンテキストを隔離する。Web認証は署名付き短命トークン（HMAC-SHA256）、**MCP認証はAPIキー（ハッシュ化して保存、Bearerトークンとして検証、v6で追加）とOAuth 2.1（JWTアクセストークンをJWKSでローカル検証、v7で追加）を併存させる**。詳細は**Clipnote設計書v13 4章**を参照。

---

## 9. データモデル（概要）

`pages`・`collections`・`collection_pages`・`page_versions`・**`api_keys`（v6で追加）**・**`jwks`・`oauth_clients`・`oauth_access_tokens`・`oauth_refresh_tokens`・`oauth_consents`（v7で追加）**を中心に構成する。`api_keys`は名前・キーのハッシュ値・マスク表示用プレフィックス・最終利用日時を持ち、ユーザー削除時に連動削除する。OAuth関連テーブルはbetter-authの`jwt`・`oauthProvider`プラグインが管理し、`apps/web`のみが読み書きする。詳細は**Clipnote設計書v13 12章**を参照。

---

## 10. 削除時のカスケード挙動

| 削除対象 | 影響範囲 |
| --- | --- |
| クリップを削除 | 更新履歴（`page_versions`）も連動削除。所属していた全コレクションから自動的に外れる（コレクション自体は残る） |
| コレクションを削除 | クリップとの関連付けのみ削除。所属していたクリップ自体は削除されない |
| **APIキーを失効（v6で追加）** | **`api_keys`行を削除。以降そのキーでのMCP認証は失敗する** |
| **連携中のアプリを失効（v7で追加）** | **該当ユーザー×クライアントの`oauth_consents`・`oauth_refresh_tokens`・`oauth_access_tokens`行を削除。既発行のアクセストークンは有効期限切れまで有効** |

---

## 11. 公開URLのシェア表示（OGP）

- publicなクリップ／コレクションは、タイトル・説明を`og:title` / `og:description`として出力する
- privateなクリップ／コレクションは、タイトルや説明などの固有情報をOGPに出力しない

---

## 12. 短命トークンの失効対策

コンテンツ配信の認証トークンは有効期限2分のため、`/p/[uuid]`・`/c/[uuid]`の親ページ側で90秒間隔でトークンを再取得し、iframeの`src`を書き換える。

---

## 13. 確認ダイアログの基準

破壊性・復元可能性に応じて確認ダイアログの要否を統一する。公開設定のトグル・メタデータ編集・「外す」操作・バージョンのダウンロードは確認不要。コンテンツ更新・バージョン復元・クリップ削除・コレクション削除・**APIキーの失効（v6で追加）**・**連携中のアプリの失効（v7で追加）**は確認ダイアログを必須とする。詳細は設計書v13 10章を参照。

---

## 14. 非機能要件

| 項目 | 内容 |
| --- | --- |
| セキュリティ | クリップ・コレクション単位で公開設定可能。デフォルトはprivate |
| コンテンツ配信 | 別ドメイン（サブドメイン）からiframeサーブ |
| コンテンツ認証（Web） | HMAC-SHA256署名付き短命トークン（有効期限2分） |
| コンテンツ認証（MCP、v6で追加） | APIキー（Bearerトークン、ハッシュ照合）／OAuth 2.1（JWTアクセストークン、JWKS検証、v7で追加。併存） |
| コンテンツサイズ | 1バージョンあたり1MB（1,048,576 bytes）を上限。管理画面・MCP共通 |
| インフラ | Cloudflare Workers + D1 に統一（web / content / mcp） |
| バージョン保持数 | 直近10件（`page_versions`） |
| Markdown編集 | 管理画面でのMarkdown編集は将来検討 |
